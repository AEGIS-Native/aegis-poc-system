# Contributing

1. Find one issue with an artifact, scope and acceptance criteria. Check existing
   claims and record yours before starting.
2. Read the current design and intended behavior. Keep approved commitments and
   identify the exact change. If requirements conflict, resolve them on the issue.
3. Submit one pull request linked to the issue. Include the result, reproduction
   steps, what was actually tested and any open limitations. A bug fix needs a
   test or named check that fails on the original defect.
4. Obtain independent review on the exact commit from a reviewer with a different
   controlling owner. Resolve findings, then a maintainer records acceptance
   after required checks pass. A changed commit needs review of the new revision.

Duplicate submissions, self-review, work outside granted scope and fabricated
results are refused. Submit only material you have the right to contribute.
Do not include credentials, private records or unpublished implementation details.
See README.md for licensing.
